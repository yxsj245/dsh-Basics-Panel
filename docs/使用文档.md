# dsh-basics-panel 使用文档

## 一、简介

「基础能力面板」是 DSH 的 Web 插件，在 **设置 → 基础能力** 中提供四个页签：

1. **MCP 服务器**：可视化、脱敏展示并开关所有 MCP 服务器。
2. **技能**：按作用域展示全部技能，支持查看与编辑。
3. **规则**：查看、创建与修改全局规则和项目级规则（AGENTS.md 兼容指令文件）。
4. **归档会话**：列出所有已归档的会话，支持恢复与删除（含批量全选删除）。

### 版本与 DSH 适配对照

| 插件版本 | 可加载的 DSH 版本 | 要点 |
|---|---|---|
| 0.4.1 | `0.1.2-rc.1` ～ `0.2.x` | 修复被 DSH `0.2.0-rc.2` 启动预检拒绝的问题：`@deepseek-ai/dsh-home-paths` peer 由 `^0.1.2-rc.1` 扩为 `^0.1.2-rc.1 \|\| >=0.2.0-rc.1 <0.3.0`；四条 `@deepseek-ai/dsh-*` devDependencies 升到 `0.2.0-rc.2`（详见第八节） |
| 0.4.0 | `0.1.2-rc.1` ～ `0.1.x` | 适配 DSH 0.1.7：会话列表快照改用 `retainedBy.mainView`，预设改读 `@deepseek-ai/dsh-agent-preset` 声明行。**在 `0.2.x` 宿主上会被启动预检拒绝**（该版本的 peer `^0.1.2-rc.1` 上界是 `<0.1.3`） |
| 0.2.0 | `0.1.2-rc.1` ～ `0.1.x` | 适配上游移除 `@deepseek-ai/dsh-client-runtime` 后的客户端服务拓扑 |

## 二、入口

打开 DSH Web 界面 → 左下角/侧边栏的 **设置** → 导航列表中的 **基础能力**。

面板顶部为页签栏：**MCP 服务器** / **技能** / **规则** / **归档会话**，点击切换。

## 三、MCP 服务器页签

### 3.1 展示方式

按作用域分组：

- **用户配置（profile）**：来自 `~/.dsh/cordis.patch.yml` 与 `~/.dsh/profiles/<name>/cordis.patch.yml`，分组名如 `用户配置 · web`。
- **预设（preset）**：来自**预设声明行**里的 MCP 行。DSH ≥0.1.7 的预设是普通的 Cordis 声明行（`@deepseek-ai/dsh-agent-preset`），组合写在该行 `config.plugins` 里，声明可以出现在 profile patch（可编辑）或随包安装的 bundle patch（**只读**，不显示文件路径）中。**没有任何 `mcp-client` 行的预设不会显示空卡片**，页面顶部会给出一句说明。
- 旧版目录式预设（`~/.dsh/.agent-presets/<id>/agent.cordis.yml`）只在宿主任旧（没有预设花名册服务）时扫描；DSH ≥0.1.7 不再读取该目录，官方迁移说明也如此，因此新版下不会把已失效的旧配置列出来。

每台服务器一行，显示：

- 状态点与文案：**已连接 · N 工具** / **已启用** / **预设作用域（随会话生效）** / **已禁用** / **未生效**；
- `serverName`、传输方式徽标（stdio / streamable-http）；
- 展开（`+`）后显示脱敏后的完整配置：命令、参数、工作目录、地址、调用超时、环境变量名、请求头名。

> **预设行的状态**：预设里的 MCP 服务器挂载在会话自己的作用域里，宿主工具表看不到它的工具，无法像 profile 行那样统计「N 个工具」。此时面板按预设组合清单显示**已启用**；若清单也不可用，则显示**预设作用域（随会话生效）**，而不会误报「未生效」。

### 3.2 开关启用

点击行尾的开关即可启用/禁用。效果：

- **用户 profile**：写入该配置文件的 `disabled` 字段，DSH 热重载通常 **3–6 秒**完成；面板在开关后会持续轮询（最多 15 秒），期间显示**生效中…（等待热重载）**，随后落到真实的**已连接 / 已启用 / 未生效**；
- **预设**：写入声明所在文件（通常是 profile patch），**对新会话生效**（已挂载的会话保持原状态，DSH 语义）。

只读文件（bundle 内声明的预设、只读模式）开关为灰色不可点。

### 3.3 安全说明

密码、API Key、请求头等敏感值**只显示为 `••••`，绝不回传明文**。DSH 当前没有项目级 MCP 组合文件，项目级 MCP 配置请关注后续版本。

## 四、技能页签

### 4.1 展示方式

按作用域分组，作用域与磁盘位置对应：

| 作用域 | 位置 | 说明 |
|---|---|---|
| 项目级 | `<项目>/.dsh/skills`、`<项目>/.agents/skills` | 优先级最高（rank 100/200） |
| 自定义 | `customSkillDirs` | 插件自定义目录 |
| 用户级 | `~/.dsh/skills`、`~/.agents/skills` | rank 400/500 |
| 内置 | 随发行版内置 | 只读 |
| 运行时 | 会话内注册 | 只读 |

同名技能按优先级显示生效版本。顶部提供搜索框与作用域过滤，点击**刷新**重新读取（技能列表与磁盘 watcher 同步）。

> **技能作用域依赖「当前会话」**：DSH ≥0.1.7 把技能提供者挂在会话预设的作用域里，只有带上会话（Agent）去读才能看到技能。面板按运行时会话列表里**主视图正在显示的那个会话**来确定作用域（DSH ≤0.1.6 用旧的 `current` 字段）。若一时确定不了（例如列表尚未就绪），面板会退到最近注册的活动会话，并在页面顶部提示「已按会话 xxxx 的技能作用域展示」；确实没有活动会话时提示「未找到活动会话」，此时只能读到全局层。

### 4.2 编辑技能

点击**可编辑**的技能行进入编辑器：

- **描述**、**使用时机**、**元数据（JSON）**：直接编辑；
- **模型可调用**、**用户可调用**：开关（对应 frontmatter 的 `disable-model-invocation` / `user-invocable`）；
- **正文**：Markdown 正文编辑。

点击**保存**后写入技能文件，DSH 的 filesystem watcher 会自动刷新（热生效）。若保存期间文件被其他来源修改，会提示「文件已被修改」，刷新后重试。

内置/运行时技能为只读，只能查看不能保存。

## 五、规则页签

### 5.1 展示方式

规则（指令）文件决定助手的行为约束，按作用域分组：

- **全局规则**：`~/.dsh/AGENTS.md`（`$DSH_HOME/AGENTS.md`），适用于所有项目与所有会话。
- **项目规则**：项目根目录至当前会话工作目录链上存在的指令文件，包括 `AGENTS.md`、`CLAUDE.md` 及各自的 `.local` 覆盖文件（`AGENTS.local.md`、`CLAUDE.local.md`），与 DSH 的 `dsh-agent-instructions` 发现逻辑一致（项目根以 `.git` 目录标记）。

每行显示文件名、展示路径、文件大小与修改时间。页签顶部显示当前会话工作目录。

### 5.2 新建规则

点击 **新建规则**，选择：

- **作用域**：全局（`~/.dsh`）/ 项目根 / 当前工作目录；
- **文件名**：`AGENTS.md` / `CLAUDE.md` / `AGENTS.local.md` / `CLAUDE.local.md`（全局作用域固定为 `AGENTS.md`）。

页面会预览目标路径。创建成功后自动进入编辑器，写入一份中文模板。若目标文件已存在，会提示「文件已存在，请直接编辑」，改为在列表中点开对应文件编辑。

### 5.3 编辑规则

点击规则行进入编辑器：直接编辑整个 Markdown 文件内容，**保存**后原子写回原文件。若保存期间文件被其他来源修改，会提示「文件已被修改」，刷新后重试。

> **生效时机**：规则在会话启动时作为基线加载，修改后**新会话生效**（当前会话保持原规则，DSH 语义）。

### 5.4 安全说明

面板只允许读写 DSH 规则发现机制认可的路径（全局 `AGENTS.md` 与项目链上的候选文件），客户端无法指定任意路径；单个规则文件读写上限为 `maxRuleBytes`（默认 1 MiB，与 DSH 的 `maxSourceBytes` 默认一致）。

## 六、归档会话页签

### 6.1 展示方式

DSH 的「归档」是**单向隐藏**：归档后的会话不再出现在侧边栏的任何分组里，但会话记录与工作区位置都完整保留。本页签把归档集合与磁盘上的会话存储列表合并展示，每行显示：

- **标题**（与侧边栏一致，取自会话列表投影；取不到时回退为会话 ID）；
- 会话 ID、工作目录；
- 创建时间、日志大小、事件条数；
- 状态徽标：**运行中**（该会话的 Agent 正在处理回合，DSH 的 `running` 状态）、**已装载**（该会话对象仍在本 DSH 进程的内存里，但处于空闲）、**文件缺失**（归档集合中的悬空条目，磁盘上已无日志文件）。

> **关于「已装载」**：归档只是一层显示过滤，它**不会关闭或卸载**会话。只要某个会话还被进程持有（典型情况是浏览器里那个标签页还开着它），它就会一直留在内存会话表里并显示此徽标——这与「正在生成回复」是两回事。鼠标悬停徽标可看到说明。

顶部工具栏显示已归档总数与合计大小、会话产物根目录（默认 `$DSH_HOME/sessions`），并提供 **全选 / 恢复选中 / 删除选中 / 删除全部 / 刷新**。

### 6.2 恢复

勾选行后点 **恢复选中**，或用行尾的 **恢复** 按钮，确认后即可把会话从归档集合中移除。它的日志与工作区分组记账从未被改动，因此会**立即回到侧边栏原来的位置**（DSH 通过工作区域变更实时推送，无需重启）。

### 6.3 删除

**删除会永久移除磁盘上的会话记录，且无法撤销**：

1. 删除该会话的日志目录 `$DSH_HOME/sessions/<项目目录>/<会话 ID>/`（含该会话的全部日志代际文件）；
2. 从工作区分组记账中摘除该会话；
3. 从归档集合中移除该 ID（悬空条目没有可删文件，只清理归档记录）。

三种删除入口：行尾 **删除**（单行）、工具栏 **删除选中**（勾选项）、工具栏 **删除全部**（页面上所有可删除的会话，等价于先全选再删除）。所有删除都会先弹出确认条并显示数量，确认后才执行；数量超过 `maxBatchIds`（默认 200）时面板会自动分批执行并合并结果。

**只有「运行中」的会话不可删除**（按钮置灰）：它的 Agent 正在处理回合，删掉产物会和正在进行的写盘交错。「已装载」但空闲的会话可以删除——确认条会额外提示其中有多少个仍装载在本次进程中（原因是它们仍在内存里，若客户端之后还给它们发消息，写入可能报错或让日志重新落盘），确认后即执行。

以下情况会被**跳过**并在结果提示里说明原因（不会误删）：

- 会话正在运行（Agent 状态为 `running`）；
- 会话不在归档集合中（本页面只管理已归档会话）；
- 目标目录不是有效的会话产物（缺少日志文件）、或路径不在会话根目录内；
- 会话 ID 无法安全映射为目录名（DSH 会对这类 ID 做转义，面板不猜测目录名）。

> **不回收的内容**：消息引用的附件（`$DSH_HOME/attachments`）等派生数据不在删除范围内。
> **侧边栏同步**：删除后本页会主动重新拉取会话列表基线；若侧边栏仍留有该行，刷新页面即可完全同步。

### 6.4 安全与兼容说明

- 恢复/删除只接受**归档集合内的**会话 ID；会话目录由 Host 侧在配置的会话根目录内**重新扫描**确定，客户端无法指定任意路径，也不会从工作目录反推目录名。
- 恢复写入的是 DSH 的工作区域（workspace）域状态：优先使用上游公开的 `unarchiveSession` API（`0.1.7-rc.1` 已提供，`0.1.5-rc.3` 尚无）；当前版本没有该 API 时，面板通过注册表自身的写入通道（同一操作队列 + `setState`）更新归档集合，使磁盘、进程内快照与工作区域变更事件保持一致；两种通道都不可用时面板会明确报错并置灰按钮，而不是只改磁盘造成状态被后续写入覆盖。
- `readOnly: true` 时本页签整体只读（不能恢复也不能删除）；`allowSessionDelete: false` 时只禁用删除，仍可恢复。
- 删除绕过 DSH 会话存储（上游未提供删除 API）：请勿在删除后于其它进程中继续使用该会话；面板会拒绝删除正在运行的会话（Agent 状态为 `running`），但对「已装载但空闲」的会话只做确认提示，不阻止——这类会话仍在本进程内存中，删除产物后若它再次落盘可能报错。

## 七、常见问题

**Q：设置里找不到「基础能力」页签？**
先确认插件确实被 DSH 加载了。最常见的两种原因：

1. **被启动兼容性预检拒绝**：DSH 启动时会核对插件 `package.json` 里每一条以 `@deepseek-ai/dsh` 开头的 peer 声明与宿主版本的匹配关系（按 `semver.satisfies(宿主版本, 范围, { includePrerelease: true })`），任一条不匹配就让整条插件不加载。本插件 `0.4.0` 曾声明 `@deepseek-ai/dsh-home-paths@^0.1.2-rc.1`，该范围覆盖 `0.1.x` 全线但上界是 `<0.1.3`，在 DSH `0.2.0-rc.2` 上判定为不满足而整条被禁用；`0.4.1` 起改为 `^0.1.2-rc.1 || >=0.2.0-rc.1 <0.3.0`。用 `dsh --profile web --dump-config` 可确认：输出里应出现 `# == dsh-basics-panel` 与 `- id: basics-panel` 两行，且全文没有 `incompatible` / `pending` 字样。
2. **profile 副本没有同步**：本插件以 `file:` 本地依赖安装，DSH 从 `$DSH_HOME/profiles/web/node_modules/dsh-basics-panel` 加载，而不是从源码仓库。`pnpm build` 只更新仓库，必须再执行 `pnpm run sync` 并重启 DSH。用 `pnpm run sync:check` 可以判断副本是否落后（退出码 1 即代表 DSH 正在运行旧代码）。

**Q：为什么某个 MCP 服务器显示「未生效」？**
它的配置有误（命令/参数/环境变量不对）导致进程没起来，或它所在的行被禁用。profile 行的热重载需要 3–6 秒，面板在开关后会轮询到状态稳定（期间显示「生效中…」），所以现在看到「未生效」基本就是真的没起来：展开该行核对命令与参数，或看 DSH 启动日志里的 mcp-client 报错。预设里的行挂载在会话作用域内，面板不会用宿主工具表去判断它，因此不会误报「未生效」。

**Q：预设分组为什么一个都没有 / 全是 0？**
DSH ≥0.1.7 的预设是普通声明行（`@deepseek-ai/dsh-agent-preset`），MCP 服务器要写在它的 `config.plugins` 里才会出现在这一页。随发行版内置的 `standard` / `ptc` / `minimal` / `cordis` 本身不含 MCP 行，所以不再显示空卡片（旧版会显示 4 个 0）。想给某个预设挂 MCP，可在自己的 profile patch 里按 Loader 行 id 覆盖该预设声明（覆盖会替换整个 `config`，需要把原有的 `plugins` 一并抄回来再加上 MCP 行），或在 profile patch 里插入一个新的预设声明。

**Q：技能页为什么是空的？**
技能按会话预设的作用域提供，面板需要拿到「当前会话」。若页面顶部提示「已按会话 xxxx 的技能作用域展示」或「未找到活动会话」，说明运行时会话列表里没有可用的当前会话（例如刚打开页面、会话还没恢复）。在会话中重新打开本面板或点「刷新」即可；仍然为空时，确认该会话的预设确实挂载了 `skill-filesystem`。

**Q：保存技能后多久生效？**
filesystem watcher 监听技能根目录，保存后一般即时刷新；若未立即生效可点击「刷新」。

**Q：为什么开关是灰的？**
该文件只读（预设声明来自安装包 bundle，或插件整体处于只读模式 `readOnly: true`）。

**Q：规则保存后当前会话为什么没生效？**
规则基线在会话启动时加载，修改仅对新会话生效，这是 DSH 的既有语义；新建会话后即可看到新规则。

**Q：为什么我的项目链规则没有显示？**
面板只显示项目根（含 `.git` 标记的目录）至当前会话工作目录链上**已存在**的候选文件（`AGENTS.md`/`CLAUDE.md`/`.local` 覆盖）。不存在的文件可通过「新建规则」创建。

**Q：恢复后侧边栏没有变化？**
恢复会立即推送归档集合变更；若侧边栏仍未出现该会话，刷新页面即可。若按钮是灰的，说明面板处于只读模式，或该 DSH 版本未暴露归档集合的写入通道（页面会给出提示）。

**Q：删除后侧边栏还留着那一行？**
客户端会话列表是页面加载时拉取的基线，删除后本页会重新拉取；若仍有残留，刷新页面即可。该行已无法打开（会话记录已删除）。

**Q：为什么某行显示「文件缺失」？**
该会话仍在归档集合里，但磁盘上的日志目录已不存在（例如被手工删除）。这类**悬空条目仍可删除**：点删除只会清理这条归档记录，不会再删文件。

**Q：徽标「运行中」和「已装载」有什么区别？**
「运行中」= 该会话的 Agent 正在处理回合（DSH 的 `AgentStatus === 'running'`），此时不能删除；「已装载」= 会话对象仍留在本次 DSH 进程的内存里，但空闲未运行，可以删除。**归档不会卸载会话**，所以浏览器标签页还开着的归档会话会长期显示「已装载」，这与「正在生成回复」无关。它一直没有消失时，关掉对应标签页或重启 DSH 后不打开它，再点「刷新」即可。

**Q：归档会话页提示「当前部署未挂载工作区注册表（workspaceRegistry）」？**
该提示表示面板在**读取的那一刻**没有拿到工作区域注册表服务。它由 `@deepseek-ai/dsh-workspace` 提供，而这个插件的启动要打开工作区域域存储、恢复未完成的写入并索引会话头，**晚于**本面板插件就绪；面板因此不在启动时缓存该服务，而是每次读取都重新解析，正常情况下不会再出现此提示。若确实看到：

- 当前 profile 没有挂载 `workspace` 行（例如裁剪过的部署）——归档功能整体不可用，属预期行为；
- 刚启动的瞬间读取——点工具栏「刷新」重试即可；
- 一直如此——检查该 profile 的 bundle 栈是否包含 `@deepseek-ai/dsh-web-app`（Web profile 的 `workspace` 行由它提供）。

**Q：删除按钮为什么是灰的？**
常见原因：面板只读（`readOnly: true`）、部署禁用了删除（`allowSessionDelete: false`）、该会话**正在运行**（Agent 状态为 `running`，需先结束该回合），或会话存储列表整体读取失败（此时无法判断可删除性，页面会给出提示）。注意「已装载」不再置灰删除按钮。

## 八、兼容性说明（DSH 0.2.0）

### 8.1 启动兼容性预检按 peer 声明判定

DSH 启动时会调用 `@deepseek-ai/dsh-app-boot` 的 `evaluatePluginCompatibility`：把插件 `package.json` 的 `peerDependencies` 里**所有 `@deepseek-ai/dsh` 与 `@deepseek-ai/dsh-*` 条目**逐条与宿主版本做 `semver.satisfies(宿主版本, 范围, { includePrerelease: true })` 判定；**只要有一条不满足，整条插件就不加载**（不会只警告）。注意 `{ includePrerelease: true }` 让预发布版本照常参与比较（例如 `^0.1.2-rc.1` 覆盖 `0.1.x` 全线，含 `0.1.5-rc.3` / `0.1.7-rc.2`），真正决定成败的是范围上界：`^0.1.2-rc.1` 的上界是 `<0.1.3`，因此覆盖不到 `0.2.0` 线。

本插件的 peer 声明与依据：

| peer | 声明范围 | 说明 |
|---|---|---|
| `@deepseek-ai/dsh-home-paths` | `^0.1.2-rc.1 \|\| >=0.2.0-rc.1 <0.3.0` | 覆盖 `0.1.x` 与 `0.2.x` 两条线；插件只取 `resolveDshHome` / `dshHomeDisplay` 两个稳定函数 |
| `@deepseek-ai/cordis` | `^4.0.2` | 不以 `dsh` 开头，**不参与**上述预检；宿主为 4.0.4，满足 |
| `@deepseek-ai/schemastery` | `^3.18.2` | 同样不参与预检；宿主为 3.18.4，满足 |
| `cordis` | `^4.0.0-rc.8`（`optional`） | 同样不参与预检 |

> 后续 DSH 再升级时，若宿主进入 `0.3.x`，本条 peer 需要再加一段元组（例如 `|| >=0.3.0-rc.1 <0.4.0`），否则会再次被启动预检拒绝。另注意 `>=0.2.0-rc.1 <0.3.0` 在 `includePrerelease` 下会放行 `0.3.0-rc.x`（放行方向比误拒安全，不必为此收紧）。

### 8.2 核对方式

```bash
dsh --profile web --dump-config          # 组合预检：无 incompatible / pending 即通过
pnpm typecheck                           # 按宿主实际类型核对（devDependencies 钉在 0.2.0-rc.2）
pnpm test                                # 局部回归
pnpm run sync:check                      # profile 安装副本是否落后于仓库构建产物
```

`--dump-config` 输出中应能看到本插件由 bundle patch 层挂载：

```yaml
# == dsh-basics-panel
- id: basics-panel
  name: dsh-basics-panel
```

### 8.3 插件未加载时的排查顺序

1. `dsh --version` 确认宿主版本；
2. 读 `~/.dsh/profiles/<profile>/node_modules/dsh-basics-panel/package.json` 的 `peerDependencies`（**注意是安装副本，不是源码仓库**）与宿主版本逐条比对；
3. 看 DSH 启动日志中的 `Plugin <name>@<version> is incompatible with dsh <runtime>: peerDependencies {...}` 一行，它直接点名未满足的 peer；
4. 若是 peer 声明问题，改 `package.json` → `pnpm build` → `pnpm run sync` → 重启 DSH；
5. 若只是副本落后（`sync:check` 报差异），`pnpm run sync` 后重启即可。

## 九、配置

插件在 `cordis.yml` 行内可配置：

```yaml
- id: basics-panel
  name: 'dsh-basics-panel'
  config:
    maxSkillBytes: 524288    # 单个技能文件编辑上限（字节）
    maxRuleBytes: 1048576    # 单个规则文件读写上限（字节）
    maxBodyBytes: 1048576    # 单次请求体上限（字节）
    readOnly: false          # 置 true 则整体只读
    extraMcpFiles: []        # 部署方额外允许编辑的 MCP 组合文件（绝对路径）
    maxBatchIds: 200         # 单次恢复/删除可处理的会话数量上限（面板会自动分批）
    allowSessionDelete: true # 置 false 则只允许恢复、禁止删除归档会话
    sessionsRoot: ''         # 会话产物根目录；留空取 $DSH_HOME/sessions
```

## 十、安装与更新

本插件以 `file:` 本地依赖方式挂在 profile 上，pnpm 在安装时会把包**复制**到 `$DSH_HOME/profiles/<profile>/node_modules/dsh-basics-panel`；DSH 的宿主半边与客户端 bundle 都从**该副本**加载，而不是从插件源码仓库加载。所以更新代码后只执行 `pnpm build` 是**看不到任何变化**的（连重启也一样），必须先同步副本：

```bash
pnpm build
pnpm run sync:check   # 校验：影响运行的文件（lib/、package.json）不一致时列出差异并返回退出码 1
pnpm run sync         # 同步构建产物到副本（默认 profile 为 web，可用 --profile 指定）
```

同步采用「目录整体替换 + 文件原地覆盖」：`cordis.patch.yml` / `LICENSE` 与仓库之间的硬链接会被保留，因此这两处配置改动依旧无需同步即生效。

同步完成后：

1. **重启 DSH 进程** —— 宿主半边（`/basics/api` 路由与各 feature 后端）在启动时载入；
2. **硬刷新浏览器（Ctrl+F5）** —— 载入新的客户端 bundle（页签由客户端 bundle 渲染）。

只改 `cordis.patch.yml` 一类的挂载配置不需要同步：该文件是硬链接，改动即时穿透，并由 profile patch 层热重载。
